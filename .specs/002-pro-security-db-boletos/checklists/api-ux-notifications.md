## Sistema de Notificações Duas Vezes ao Dia (09:00 / 18:00)

- [ ] CHK007 - Os requisitos do motor de alertas (`FR-014`, `SC-004`) definem explicitamente a janela de tolerância após o horário configurado (ex.: atraso de execução do worker ou abertura do app minutos após `09:00`/`18:00`) e o fuso horário adotado pelo servidor para disparo de e-mails? [Ambiguity, Gap, Spec §FR-014, §SC-004]
- [ ] CHK008 - A regra anti-duplicação por turno (`Spec §Edge Cases`, `SC-004`) esclarece se o controle "uma notificação por turno" aplica-se de forma independente a cada canal (In-App, Notificação Local, E-mail) ou coordenada entre canais, e como reage caso o usuário altere os horários na aba `Mais` no meio do mesmo dia? [Ambiguity, Edge Case, Spec §Edge Cases, §FR-015, §SC-004]
- [ ] CHK009 - Existe alinhamento semântico entre `FR-014` (boletos que vencem em até 3 dias, hoje ou vencidos) e `FR-011b` item a (lembretes de `is_credit_card_charge` "na data de cobrança"), deixando claro se cobranças embutidas no cartão também disparam nos 3 dias anteriores e como o filtro de "3 dias" trata hora vs data calendário? [Conflict, Ambiguity, Spec §FR-011b, §FR-014]
- [ ] CHK010 - O requisito de alerta para cartão que excede o teto saudável (`US5 §3`, `FR-020`) define o gatilho exato, a severidade na Central de Notificações e se esse alerta se limita à Central In-App ou inclui notificações locais/e-mail? [Gap, Clarity, Spec §US5, §FR-020]
- [ ] CHK011 - Os requisitos de notificação nativa/local e de navegador (`FR-015`, `Constitution §I`) especificam o comportamento degradado caso o usuário recuse permissões de notificação do sistema operacional/browser ou mantenha o dispositivo offline/fechado no horário programado? [Gap, Exception Flow, Spec §FR-015]
